## Practical next gates

1. Run the signed/unsigned C2PA fixture through the browser UI and document WASM load time, memory and trust configuration. The [C2PA SDK](https://github.com/contentauth/c2pa-js/tree/main/packages/c2pa-web) describes on-demand WASM verification.
2. Build a labeled reliability corpus including pristine camera JPEG, custom tables, multi-step edit chains, transparency and non-multiple-of-eight dimensions. Keep source bytes, transform recipe, ground-truth masks and split manifest. Make confidence wording contingent on held-out false alarm rates.
3. Prototype model inference outside the default app. The [PixRestore repository](https://github.com/csslc/PixRestore) publishes inference code and checkpoints with Python/DINO dependencies. The [SAM 3 repository](https://github.com/facebookresearch/sam3) documents Python 3.12+, PyTorch 2.7+, CUDA 12.6+ and checkpoint access. Record model licenses, sizes, latency, memory and output hashes before connecting a service.
4. Add browser-level tests for file replacement during an in-flight C2PA read, route switching with named regions, mask upload, report export and worker cancellation. This runtime's cloud browser blocks localhost, so these remain unverified here.
5. Bound local receipt storage and add an atomic operation outcome: a full `localStorage` can currently reject a receipt after an output is computed. Make the failure explicit and preserve a downloadable receipt or choose durable storage.
